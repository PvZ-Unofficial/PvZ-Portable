## 审阅方法

1. 依时间顺序检查上述 332 个提交的标题、改动文件和函数级补丁；对“大量小
   修复”、跨平台迁移等混合提交展开逐 hunk 检查，而不按提交标题直接分类。
2. 用当前 1051 反编译源码确认候选差异仍是否存在，并用 `git log -S`、
   `git blame` 和后续提交判断当前 Portable 是否仍保留该行为。
3. 对会改变规则、状态机、时序、边界或可交互流程的候选，用指定 GNU
   `objdump -d -M intel` 核对原版；声称是年度版差异的项目同时核对 1.2.0.1073。
4. 检查 `references/zhihu/wszqkzqk/articles/` 的全部 28 篇文章标题，并详读与
   存档、资源 ID、回放、输入、音乐、性能、对象生命周期和安全修复有关的文章。
   这些文章解释了多项移植修改的动机，但没有给出台账之外的新官方核心规则。
5. 按用户指定边界排除行为不变的性能/重构、UI 设计、纯视觉/音频、构建平台
   适配及 UB 防护；若提交同时含核心逻辑，仍拆出核心部分单独记录。

## 保留但不作为 1051 逻辑还原项的功能修改

以下修改确实会影响运行结果，但其目标是让 Portable 的跨平台实现、存档或工具
路径可用，不是年度版规则，也不是应反向移植进 1051 反编译项目的逻辑：

- `c96b300…` 起的 V4 跨架构存档、`2dbe06d…` 的统一存档清理，以及本分支为
  奖励/资源迁移加入的兼容字段。这些是 Portable 的持久化协议，不能按原版
  内存镜像实现机械回退。
- `6e91c66…` 修复资源变量值到 ID 的映射，解决 64 位 Portable 载入植物僵尸
  后贴图损坏；1051 反编译源码本来使用 `*(int*)gResources[i]`，错误来自早期
  移植后的地址/值混淆，并非 1051 反编译错误。
- `5b92b79…` 在继续对话框退出时设置 `BOARDRESULT_QUIT`、`4e4f5e1…` 暂停时
  保存，以及退出/关闭流程的配套修改，服务于 Portable 自己的存档保留策略。
- `77f63b1…` 把打僵尸锤子动画的创建从 `CursorObject` 构造移到
  `Challenge::StartLevel`。1051 二进制确实在构造函数中创建锤子；Portable 的
  调整解决其对象初始化顺序，正常可观察行为保持一致，因此不列为版本差异。
- `c055083…`、`7df9834…` 的确定性时钟和录制回放分支只在 Portable demo
  session 中生效，属于开发/回放工具能力。
- `c4297dd…` 中清空 `mCrazyDaveDialogStart`、阻止普通 `AnimateBoard` 在
  Upsell 重复启动台词的 hunk，是 D32/D33 修复在 Portable 生命周期下的配套
  实现；原版二进制没有相同语句，不能连同两项确定的反编译修复一起照搬。

- UB、崩溃和边界硬防护：指针宽度、对象生命周期、数组初始化、整数溢出、

## 完整性结论

在上述历史范围、当前源码和两个指定官方二进制内，没有再发现未分类的核心
规则、状态机、时序或交互流程修改。后续若上游 0.2.2 之后增加提交，应以本文件
的终点为增量基线继续审阅，而不是重新把现有 332 个提交全部归类。
