## 审阅方法

1. 先检查完整 907 个提交的标题和改动路径，再依时间顺序检查 332 个核心目录
   候选的函数级补丁；对“大量小修复”、跨平台迁移等混合提交展开逐 hunk
   检查，而不按提交标题直接分类。
2. 用当前 1051 反编译源码确认候选差异仍是否存在，并用 `git log -S`、
   `git blame` 和后续提交判断当前 Portable 是否仍保留该行为。
3. 对会改变规则、状态机、时序、边界或可交互流程的候选，用指定 GNU
   `objdump -d -M intel` 核对原版；声称是年度版差异的项目同时核对 1.2.0.1073。
4. 检查 `references/zhihu/wszqkzqk/articles/` 的全部 28 篇文章标题，并详读与
   存档、资源 ID、回放、输入、音乐、性能、对象生命周期和安全修复有关的文章。
   这些文章解释了多项移植修改的动机，但没有给出台账之外的新官方核心规则。
5. 按用户指定边界排除行为不变的性能/重构、UI 布局设计、纯绘制/音频、构建
   平台适配及不改变正常状态机的 UB 防护。改变交互权限的流程仍按交互检查；
   混合提交中的核心部分单独记录。确属反编译错误的展示/音频项可以留在 D 台账
   供后续修正，但必须明确标为非核心。
6. 提交 `49b00fe6fe0fbb1da76057bd991ef03d74ac0a37` 后，使用独立上下文重新筛选
   全区间并复核源码与两个二进制；该复核发现 V10、Limbo 功能和松鼠历史曾被
   漏分，并纠正 D24、B6、V9 和统计口径，结果已回填本文件及对应台账。

## 保留但不作为 1051 逻辑还原项的功能修改

以下修改确实会影响运行结果，但其目标是让 Portable 的跨平台实现、存档或工具
路径可用，不是年度版规则，也不是应反向移植进 1051 反编译项目的逻辑：

- `c96b300…` 起的 V4 跨架构存档、`2dbe06d…` 的统一存档清理、
  `1ed8f5c…` 的奖励已生成存档清理，以及本分支为奖励/资源迁移加入的兼容
  字段。这些是 Portable 的持久化协议，不能按原版内存镜像实现机械回退。
- `6e91c66…` 修复资源变量值到 ID 的映射，解决 64 位 Portable 载入植物僵尸
  后贴图损坏；1051 反编译源码本来使用 `*(int*)gResources[i]`，错误来自早期
  移植后的地址/值混淆，并非 1051 反编译错误。
- `5b92b79…` 在继续对话框退出时设置 `BOARDRESULT_QUIT`、`4e4f5e1…` 暂停时
  保存、`d0f3ffc…` 在音乐关闭前保存，以及退出/关闭流程的配套修改，服务于
  Portable 自己的存档保留和音频位置恢复策略。
- `7be50db…` 在进入禅境花园和打开商店时刷新时间，补偿 Portable 复用
  `ZenGarden` 对象的生命周期；这是保证花园计时继续反映真实当前时间的移植
  配套，不是应恢复成旧缓存值的官方规则差异。
- `8ce44b0…`、`266224c…` 在点击时读取实时鼠标位置，解决 Portable 主循环先

## 完整性结论

经过完整 907 个提交的标题/路径筛选、332 个核心目录候选的函数级检查、当前
源码核对、两个指定官方二进制裁决及独立上下文复核，已确认的规则、状态机、
时序和交互流程修改均已进入 D/B/V、保留项、历史已撤销项或排除项。该结论受
现有二进制符号、触发路径和用户指定范围约束，不把原始台账数误称为核心项数。
后续若上游 0.2.2 之后增加提交，应以本文件的终点为增量基线继续审阅；同时应
保留全区间标题/路径筛选，不能只检查这 332 个既有核心目录候选。
